# Hooked Shorts 官网：你需要亲自完成的步骤（详细版）

仓库里的 **代码已经写好**，电脑本地用 `npm run dev` 也能预览。但要让 **全世界** 通过 `https://hookedshorts.com` 打开、并用于 **TikTok 开发者审核**，你必须在 **浏览器里** 完成下面几件事（别人无法替你登录账号）。

---

## 总览：你要完成的三件事

| 顺序 | 做什么 | 目的 |
|------|--------|------|
| 1 | 把网站**部署到公网**并绑上 **hookedshorts.com** | 审核员能打开你的公司站、隐私政策链接 |
| 2 | 让 **admin@hookedshorts.com** 能**收到邮件** | 表上填的邮箱真实可用 |
| 3 | 在 **TikTok for Business 开发者**页面**填表并提交** | 完成注册/审核 |

下面按顺序写「点哪里、填什么」。若某一步你的界面和描述略有不同，以**当前平台页面上的文字**为准。

---

## 方式 A：GitHub Pages（本仓库已配好自动部署，优先看这个）

代码推到 **main** 后，**Actions** 会自动构建并发布本站点。你还需在 GitHub 上开一次开关，并在域名里加记录。

### A.1 先确认代码已推送

在你电脑上项目根目录执行 `git push`，把 `hookedshorts-site/` 和 `.github/workflows/` 推上去。

### A.2 在 GitHub 打开 Pages 源

1. 打开仓库 [github.com/hehe-collab/cursor-project](https://github.com/hehe-collab/cursor-project)（若你的仓库名不同，进你自己的 `cursor-project` 仓库即可）。
2. **Settings** → 左侧 **Pages**。
3. **Build and deployment** → **Source** 选 **GitHub Actions**（不要选 “Deploy from a branch” 除非你知道自己在做什么）。

### A.3 看部署是否成功

1. 打开 **Actions** 标签，找到 **“Deploy Hooked Shorts to GitHub Pages”**，应显示绿色成功。
2. 成功后再到 **Settings → Pages**，会看到一个站点地址。  
   - **请使用自定义域名** `https://hookedshorts.com` 访问，不要用 `*.github.io/仓库名` 的默认地址来验收（静态资源路径按根域配置，**默认的 project 的 github.io 子路径可能样式会挂**）。  
3. 仍在 **Settings → Pages** → **Custom domain** 填：`hookedshorts.com` → Save。按页面提示在 **Namecheap**（或你买域的地方）给域名加 **DNS**（A 记录到 GitHub Pages 的 IP 或 CNAME 到 `你的用户或组织.github.io`，**以 GitHub 显示为准**）。  
4. 等待 DNS 生效（常几分钟到 48 小时）→ 勾选 **Enforce HTTPS**（能勾时再勾）。

完成 A.1～A.3 后，用 **https://hookedshorts.com** 和 **https://hookedshorts.com/privacy** 在浏览器中打开为正常页面即可。

### A.4 和下面「Vercel」二选一即可

同一段官网 **不要** 同时在 Vercel 和 GitHub Pages 各指一遍同一域名，择一即可。已用 GitHub Pages 时不用再做下面 Vercel 的「同域名」步骤。

## 第一步：把网站部署出去（可选：Vercel，和 GitHub Pages 二选一即可）

### 1.1 准备

- 有一个 **GitHub** 账号（若没有，到 [github.com](https://github.com) 注册）。
- 把你的项目 **推送到 GitHub 上的一个仓库**（可以是私人仓库）。

**若你还不会推代码到 GitHub**，在电脑终端里（先 `cd` 到「包含 `hookedshorts-site` 文件夹」的那个项目根目录）：

```bash
git status
git add hookedshorts-site .github
git commit -m "Add Hooked Shorts site and CI"
git push
```

（若从未绑过远程仓库，需要先在 GitHub 建一个空仓库，再按 GitHub 页面提示 `git remote add origin ...`。）

### 1.2 在 Vercel 上新建项目

1. 打开浏览器访问：[vercel.com](https://vercel.com) ，用 GitHub 登录。
2. 进入 **Dashboard** → **Add New…** → **Project**。
3. **Import** 你的 Git 仓库。
4. 在配置里找到 **Root Directory（根目录）**，点 **Edit**，填：`hookedshorts-site`  
   （因为网站代码在这个子文件夹里，不是仓库根目录。）
5. **Framework Preset** 选 **Next.js**（一般会自动识别）。
6. **Build Command** 保持默认 `next build` 即可。  
7. **Output Directory**：若界面有这项，且你部署后打开是 404，再试填 **`out`**（本项目是静态导出，产物在 `out/`）。很多情况下 Vercel 选 Next.js 后会自动处理，不必手填。
8. 点 **Deploy**，等构建变绿（成功）。

### 1.3 绑定你的域名 hookedshorts.com

1. 在 Vercel 里打开这个 **Project** → **Settings** → **Domains**。
2. 添加域名：`hookedshorts.com`，需要的话再添加 `www.hookedshorts.com`。
3. Vercel 会显示要你在**域名注册商**（例如 Namecheap）里添加的 **DNS 记录**（可能是 A 记录、CNAME 等）。**按 Vercel 页面上显示的逐条添加**，不要照抄别人的截图。
4. 在 Namecheap（或你买域名的网站）→ 该域名的 **DNS / Advanced DNS** → 保存记录。一般 **几分钟到几小时** 生效。
5. 浏览器访问：`https://hookedshorts.com`  
   - 应能打开网站，地址栏有**小锁**（HTTPS）。  
   - 再试：`https://hookedshorts.com/privacy` 能打开隐私政策。

### 1.4 若你不用 Vercel，用 Cloudflare Pages（简要）

1. 登录 [Cloudflare](https://dash.cloudflare.com) → **Workers & Pages** → **Create** → **Pages** → Connect to Git。
2. 选仓库，**Root directory** 填 `hookedshorts-site`。
3. Build command：`npm run build`，**Build output directory**：`out`。
4. 在 Pages 项目里 **Custom domains** 添加 `hookedshorts.com`，按提示改 DNS。

## 第二步：让 admin@hookedshorts.com 能收信

网站页脚和隐私里写的是 **`admin@hookedshorts.com`**。审核方可能发测试邮件，**必须能收到**。

任选一种方式：

### 方式 A：Cloudflare Email Routing（免费转发，适合已有 CF 管 DNS）

1. 把 `hookedshorts.com` 的 **DNS 放在 Cloudflare**（或按 Cloudflare 说明接入）。
2. Cloudflare 控制台 → **Email** → **Email Routing**。
3. 添加目标地址（你的个人 Gmail/企业邮），再创建 **admin@hookedshorts.com** 转发到该地址。
4. 按提示在 DNS 里加 **MX**（若由 Cloudflare 托管 DNS，通常会提示自动加）。

### 方式 B：Google Workspace / 微软 365（付费企业邮箱）

1. 购买并验证域名 `hookedshorts.com`。
2. 在管理后台创建用户或别名 **admin@hookedshorts.com**。
3. 按向导在注册商处填好 **MX 记录**。

### 方式 C：Namecheap 邮箱或转发

若 Namecheap 提供 **Email Forwarding** 或 **Private Email**，按他们说明把 **admin@** 转发到你的常用邮箱。

### 自测

用自己邮箱给 **admin@hookedshorts.com** 发一封「测试」，确认 **能收到**（若进垃圾箱，注意以后从该地址回复时专业一些）。

## 第三步：在 TikTok for Business 开发者（或类似入口）填表

1. 打开你要注册的开发站（你之前用的 **TikTok API for Business / Developer** 页面）。
2. **公司网址**：填 `https://hookedshorts.com`（或你实际部署后的主域，需与线上一致）。
3. **Privacy Policy URL**：`https://hookedshorts.com/privacy`
4. **Terms of Service URL**：`https://hookedshorts.com/terms`（若表单要填）
5. **公司英文名称**：与网站页脚、[`lib/site.ts`](lib/site.ts) 里 `legalEntityEn` 一致：  
   `Suzhou Jingyu Heyao Network Information Technology Co., Ltd.`  
   若执照上英文不同，**应先改 `lib/site.ts` 并重新部署**，再填表。
6. **联系邮箱**：填 `admin@hookedshorts.com`（或你实际能收信且与网站一致的企业邮）。
7. **英文说明**（计划如何使用 API/数据）：用**真实业务**写，与网站「短剧推广、投放」一致即可，不要抄与业务不符的话术。

提交前用**无痕窗口**或**手机**再打开上述 **https** 链接，确认无证书错误、不是 404。

## 可选：让 GitHub 自动检查代码

当你把包含 [`.github/workflows/hookedshorts-site.yml`](../.github/workflows/hookedshorts-site.yml) 的提交推到 GitHub 后，每次改 `hookedshorts-site` 里的文件，会自动跑 **lint + build + verify**。  
你在 **GitHub 仓库 → Actions** 里能看到绿勾/红叉。红叉表示要修代码后再部署。

## 常见问题

**Q：本地 `localhost:3210` 能开，但网上打不开？**  
A：说明没部署成功或域名没指到托管商。先确认 Vercel/CF 里 **部署成功**，再确认 **DNS 已按平台要求改好**。

**Q：提示端口被占用（EADDRINUSE）？**  
A：在项目 `hookedshorts-site` 目录执行 `npm run dev:force`，或看该目录下 [README.md](README.md) 里「端口被占」一节。

**Q：执照上公司英文名和网站不一样？**  
A：改 `hookedshorts-site/lib/site.ts` 里的 `legalEntityEn`，然后 `npm run build` 并在托管商上**重新部署**，再填 TikTok。

完成 **第一步 + 第二步 + 第三步** 后，你的「上线 + 过审准备」在工程上就算齐活了。若某一步卡在某一个平台的具体按钮上，你可以说明是 **Vercel / Namecheap / Cloudflare / TikTok** 哪一页，再针对性问。
